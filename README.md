# The IDMC Vendor Portal for Secure Agent Updates
The tool will allow developers to access the IDMC Secure Agent directories through the GUI based on their credentials to allow different teams for adding / removing add-ons and drivers.

# IDMC-Vendor-Portal: Read Before Your Setup
  - USER_MANUAL.md --> End user manual
  - ARCHITECTURE.md --> Architecture Document
  - DEPLOYMENT.md --> Detail on how to deply the solution
  - dev-setup-mac.sh --> setup script for Linux / Mac
  - dev-setup-windows.ps1 --> setup script for Windows
  - after the script runs, it will echo instructions on how to run the servers


Notes: 
  - Make sure secrets (.pem) are created, and Google Authenticator is add to the end user Mobile.
  - Ports are allowed
  - 3 Servers will be running; Security[Python], Backend[Python], Frontend[HTML]
  - You can also run using Containers.
  - LLM Key is available
  - Firt time Admin user is set [one-time python script "seed_admin.py"]
  - **This is unsupported, as-is code**

## Known Issues (found running this copy, Oct 2026)
  - **Docker path is currently broken.** `backend-api/requirements.txt` pins `pip==21.2.4`, which crashes under Python 3.12 inside the `python:3.12-slim` image (`AttributeError: module 'pkgutil' has no attribute 'ImpImporter'`). The `docker compose up --build` path fails on the `backend-api` image build. Use the native `dev-setup-mac.sh` / `dev-setup-windows.ps1` path instead until this is fixed — see [NATIVE_SETUP.md](NATIVE_SETUP.md).
  - **If you copy/move this project folder**, `.env.local` and `local-data/log_paths.local.yaml` (both generated by the setup script) store **absolute paths** to the old location and will not auto-update. Re-run the setup script after deleting `.env.local`, or manually fix the paths — see the "Moved or copied project folder" note in [NATIVE_SETUP.md](NATIVE_SETUP.md#moved-or-copied-project-folder).
  - **⚠️ Secrets are committed to git in this repo** — there is no `.gitignore`. `jwt_private.pem` / `jwt_public.pem` (root, `auth-service/`, and `local-data/`), `.env.local`, and `local-data/llm-settings.enc` are all tracked and contain real generated key/secret material (checked: no live LLM API key or third-party credential was found hardcoded, but the RSA signing keys and HMAC secrets in these files are real). Treat this repo as compromised for JWT/session trust if it is ever made public — rotate `JWT_SIGNING_KEY`/`JWT_PUBLIC_KEY`, `ADMIN_API_KEY`, `ADMIN_SESSION_SECRET`, and `UPLOAD_TOKEN_SECRET`, and add a `.gitignore` before any further commits. See [DEPLOYMENT.md §22 Security Checklist](DEPLOYMENT.md#22-security-checklist).
